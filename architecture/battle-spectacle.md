# Спецификация зрелищности и награды

Статус: текущая версия реализована в прототипе как `spectacle-v1`.

Документ описывает оценку зрелищности боя, её поэтапное отображение в replay и
условную финальную награду. Основной контракт боя находится в
[battle-engine.md](battle-engine.md), правила показа — в
[battle-visual.md](battle-visual.md).

## 1. Граница ответственности

Зрелищность является производным результатом уже произошедших действий. Она не
влияет на порядок ходов, урон, инициативу, выбор победителя, шанс критического
удара или травмы.

```text
BattleEngine → SpectacleState в каждом snapshot → визуальный слой
             → финальный SpectacleResult → BattleReward
```

Расчёт выполняет боевой движок. Визуальный слой получает готовые `score` и
`tier`, не вычисляет их повторно из здоровья и не меняет награду.

## 2. Контракт

```ts
type SpectacleTier =
  | "boring"
  | "ordinary"
  | "exciting"
  | "grand";

interface SpectacleFactors {
  completedSteps: number;
  duration: number;    // 0…1
  exhaustion: number;  // 0…1
  balance: number;     // 0…1
  lastBreath: number;  // 0…1
  traumaCount: number;
  traumaBonus: number; // 0…0.20
  techniqueBonus: 0;   // зарезервировано, в v1 не участвует
}

interface SpectacleState {
  formulaVersion: "spectacle-v1";
  score: number; // целое 0…100
  tier: SpectacleTier;
  factors: SpectacleFactors;
}

type SpectacleResult = SpectacleState;

interface BattleReward {
  formulaVersion: "spectacle-half-v1";
  amount: number; // целое 0…50
}
```

`SpectacleState` записывается в каждый `BattleSnapshot` и `BattleReplayState`.
Финальный `BattleResult` содержит `spectacle: SpectacleResult` и
`reward: BattleReward`. Тип валюты пока не определён.

## 3. Формула `spectacle-v1`

Длительность измеряется количеством полностью завершённых боевых действий.
Реальное время анимаций, приветствия и случайных пауз интерфейса не учитывается.

```text
healthA = clamp(currentHealthA / effectiveStartHealthA, 0, 1)
healthB = clamp(currentHealthB / effectiveStartHealthB, 0, 1)

duration   = clamp((completedSteps - 4) / (36 - 4), 0, 1)
exhaustion = 1 - (healthA + healthB) / 2
balance    = 1 - abs(healthA - healthB)
lastBreath = exhaustion * (0.65 + 0.35 * balance)

traumaCount = count(trauma.source == "battle")
traumaBonus = min(0.20, traumaCount * 0.08)

rawScore = round(100 * clamp(
  0.18 * duration
  + 0.34 * lastBreath
  + 0.28 * duration * lastBreath
  + traumaBonus,
  0,
  1
))

score = max(previousSnapshot.score, rawScore)
```

Первые четыре действия не дают очков длительности. К 36-му действию компонент
длительности достигает предела. Значения `4` и `36` являются параметрами
ruleset и могут быть откалиброваны по статистике боёв.

`exhaustion` показывает, насколько исчерпан общий запас здоровья обоих бойцов.
`balance` повышает оценку, если оба дошли до схожего тяжёлого состояния.
`duration * lastBreath` создаёт отдельный драматический бонус: высокую
оценку получает долгий бой, в котором оба гладиатора держались почти до
последнего. Уменьшенные веса и более длинная шкала длительности замедляют обычный
рост: идеальный бой без травм набирает не более 80 очков. Затянутый безопасный
бой или короткий обмен большим уроном сами по себе максимум не дают.

Каждая новая травма с `source = "battle"` добавляет 8 очков. Общий бонус
ограничен 20 очками. Стартовые травмы и послебоевые последствия с
`source = "starting-injury"` или `source = "outcome"` не учитываются: публика
награждает только травматичные события, произошедшие на текущей арене.

Формула симметрична и применяется одинаково к победе и ничьей. Отрицательное
здоровье ограничивается нулём. Оценка не уменьшается между snapshots: лечение
не отменяет уже увиденный зрителями драматичный момент.

## 4. Уровни

| Очки | Tier | Текст интерфейса |
|---:|---|---|
| 0–24 | `boring` | Скучный бой |
| 25–49 | `ordinary` | Обычный бой |
| 50–74 | `exciting` | Захватывающий бой |
| 75–100 | `grand` | Грандиозный бой |

Tier нужен для словесной оценки и визуального оформления. Все экономические
расчёты используют точное числовое значение `score`.

## 5. Финальная награда

Первая условная формула:

```text
reward = floor(finalSpectacle.score / 2)
```

Награда создаётся только после завершения боя и лежит в диапазоне `0…50`.
Промежуточные snapshots показывают зрелищность, но не создают частичную награду.

## 6. Отображение

Во время replay ниже `VS`, на уровне значков состояний, показываются золотистые
театральные маски и текущий `score`. В итоговом snapshot поверх арены появляется
крупное словесное название tier, а под ним — точное значение и награда. Полные
размеры, цвета и правила доступности
описаны в [визуальной спецификации](battle-visual.md#зрелищность-в-hud-и-над-ареной).

## 8. Проверки

- каждый snapshot содержит `SpectacleState`;
- `score` является целым числом от 0 до 100;
- `score` не уменьшается по ходу replay;
- долгий бой двух почти истощённых бойцов получает tier `grand`;
- долгий бой бойцов с полным здоровьем не получает максимальную оценку;
- каждая из первых двух боевых травм добавляет 8 очков;
- бонус трёх и более травм ограничивается 20 очками;
- стартовые и послебоевые травмы не добавляют зрелищность;
- финальный `BattleResult.spectacle` совпадает с последним snapshot;
- `BattleReward.amount = floor(score / 2)`;
- визуальный слой не пересчитывает зрелищность самостоятельно.
