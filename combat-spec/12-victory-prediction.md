# Прогноз победы

## 21. Назначение и границы

Прогноз победы — статистическая оценка исходов серии полных боевых симуляций с
текущими настройками. Это не отдельная упрощённая формула сравнения характеристик:
каждый прогон выполняет обычный `BattleEngine.simulate()` и проходит все правила
боя, включая инициативу, усталость, удары, классовые приёмы, травмы, временные
модификаторы, победу и ничью по лимиту итераций.

Калькулятор относится к симулятору и не изменяет контракт разрешения одного боя.
Он не меняет текущий replay, введённый пользователем seed или состояние уже
рассчитанного боя.

## 22. Входные данные

Перед началом серии калькулятор один раз создаёт снимок текущего `BattleInput`:

- оба бойца со всеми базовыми характеристиками;
- классы, оружейные комплекты и комплекты доспехов;
- постоянные перки, стартовые бафы, дебафы и травмы;
- тип арены и множители поддержки;
- максимальное число итераций;
- выбранный пользователем базовый `seed`;
- версия схемы и правил, которую нормализует движок.

Количество прогонов `sampleCount` задаётся пользователем и должно быть целым
положительным числом из предложенного симулятором диапазона. Текущий интерфейс
предлагает `20`, `50`, `100` и `250` прогонов; обычным значением считается `100`.

Выбранный `buffLoadout` остаётся частью входа, но расписание ручных команд для
прогноза всегда пустое:

```ts
playerBuffCommands: []
```

Калькулятор не должен автоматически подбирать выгодный ход применения бафа: это
создало бы неизвестную стратегию игрока и сделало прогноз несопоставимым с
обычным боем. В будущем стратегии применения могут быть отдельным явно выбранным
параметром прогноза.

## 23. Формирование выборки

До формирования выборки калькулятор один раз выполняет бой с исходным `baseSeed`.
Этот результат показывается отдельно как детерминированный исход текущего seed и
не включается в статистическую выборку. Повтор такого боя с теми же входными
данными даст тот же результат.

Для прогона с индексом `i`, начиная с единицы, создаётся независимая копия
исходного ввода. Seed прогона формируется детерминированно:

```text
simulationSeed(i) = baseSeed + "::prediction-" + i
```

После этого выполняется:

```ts
const result = new BattleEngine(simulationInput).simulate();
```

Все прогоны используют одинаковые настройки, версию правил и порядок обработки;
различается только seed. Поэтому одинаковые входные данные, базовый seed,
`sampleCount` и версия правил обязаны давать одинаковый прогноз.

Прогноз строится только по успешно завершённой выборке. Ошибка валидации или
симуляции не должна создавать частичный процент: интерфейс показывает ошибку и
предлагает исправить настройки.

## 24. Агрегация результата

Для каждого прогона учитывается `BattleResult.outcome`:

- `victory` добавляет одну победу бойцу из `outcome.winnerId`;
- `draw` добавляет одну ничью;
- `BattleResult.steps` добавляется к общей длительности.

Проценты вычисляются относительно всех прогонов, включая ничьи:

```text
fighterWinRate = fighterWins / sampleCount
drawRate       = drawCount / sampleCount
averageSteps   = sum(result.steps) / sampleCount
```

Для доли побед каждого бойца дополнительно показывается 95%-й интервал Уилсона:

```text
p = fighterWins / sampleCount
z = 1,96
center = (p + z² / (2n)) / (1 + z² / n)
margin = z × sqrt(p(1 − p) / n + z² / (4n²)) / (1 + z² / n)
interval = [center − margin, center + margin]
```

Интервал ограничивается диапазоном `[0; 1]`. Он показывает неопределённость
конечной выборки: отображаемая точка `70%` при небольшом числе прогонов не должна
интерпретироваться как точное значение без погрешности.

Инвариант выборки:

```text
wins(fighter1) + wins(fighter2) + drawCount = sampleCount
```

Победой считается боевой исход, а не послебоевая судьба гладиатора. Возможная
гибель победителя после боя не превращает его победу в ничью или поражение.

## 25. Интерпретация

Показанный процент является эмпирической частотой внутри выбранной выборки, а не
гарантией и не точной вероятностью для одного конкретного seed. Маленькая выборка
считается быстрее, но сильнее меняется от набора seed; большая выборка обычно
стабильнее, но требует больше времени.

Симулятор обязан показывать:

- имя и долю побед каждого бойца;
- абсолютное число побед и размер выборки;
- детерминированный исход боя для текущего seed отдельно от общей выборки;
- 95%-й диапазон оценки для доли побед каждого бойца;
- долю ничьих;
- среднее количество итераций;
- предупреждение об исключении ручных команд бафов;
- пояснение, что прогноз не гарантирует исход конкретного боя.

Изменение любого боевого входного параметра делает ранее показанный прогноз
устаревшим. Симулятор должен явно потребовать пересчёт и не оставлять старые
проценты как будто они относятся к новым настройкам.
